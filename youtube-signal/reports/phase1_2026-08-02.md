## Step 1 — the date-sort test. **OUTCOME B (partial).**

Three mechanisms tested against a relevance baseline on 3 queries, and — this is
the part that matters — **verified by pulling real upload dates**, not by checking
that results came back.

### What works: the date filter

`sp=EgIIBQ%3D%3D` (YouTube's "past 12 months" search filter), passed through a
`/results?search_query=…&sp=…` URL that yt-dlp's search-URL extractor accepts.

| query | within 12 months | max age | baseline within 12mo | baseline max age |
|---|---|---|---|---|
| kalshi api python | **10/10** | 6.4 mo | 9/10 | 23.3 mo |
| polymarket clob api | **9/9** | 8.0 mo | 7/10 | 23.3 mo |
| how to build a trading bot | **10/10** | 10.0 mo | 8/10 | 35.7 mo |

Jaccard against the unfiltered baseline is 0.47–0.67, with 5–9 of 25 results new —
so it returns a materially different set, not a reordering. The window is
**rolling, not calendar-year**: a 2025-10-03 video survives on 2026-08-02.

### What does not work: the date sort

`sp=CAI%3D` (sort by upload date) **is ignored.**

| variant | fraction of adjacent pairs in newest-first order |
|---|---|
| relevance baseline | 0.556, 0.556, 0.667 → mean **0.593** |
| sort_by_date | 0.556, 0.556, 0.667 → mean **0.593** |

Identical, and 0.5 is chance. Adding the sort field to the filter token changes
nothing (same result set, Jaccard 1.0). It returns the same videos in an order no
better than search nondeterminism.

`yt-dlp`'s own `daterange` option is not an alternative: under `extract_flat`,
0/10 entries carry an `upload_date`, so it filters nothing. Turning `extract_flat`
off costs a full player fetch per result — roughly 50× the server-side filter.

### Consequence

**F3 is a date-WINDOWED relevance family, not a date-ORDERED one.** That is a real
query family — it surfaces videos the unfiltered families miss — but it is not what
the brief specified, and it should be expected to overlap F1/F2 more than intended.
See 7c for whether it did.

**No API key is required to proceed.** A key would buy true `order=date` for
8 × 100 = 800 units, comfortably inside the 10,000/day budget, and that is the
remedy if the 7c overlap is judged too high.
